## C2 — gamma engine (2026-09-09, MacBookPro18,1 M1 Pro, macOS 27.0 26A5416b, built-in display only)

Screenshots can't show a gamma tint (see the C0 row above), so every check below verifies by reading the live gamma table back directly with `CGGetDisplayTransferByTable` — a precise, vision-free check of the actual OS-level state, not an inference. Verification ran against **the real compiled `Dimit.app` binary**, not a reimplementation: a standalone probe copies the actual `Dimit/Display/*.swift` and `Dimit/App/AppState.swift` source files (same technique as C1's popover render check) and drives them directly, and separately the real `Dimit.app` was launched with its persisted state pre-seeded to `isOn: true` via `UserDefaults(suiteName: "app.dimit.mac")` from outside the process.

| Check | Result | Notes |
|---|---|---|
| 0K sets green/blue to exactly 0, preserves red | pass | Real pipeline (AppState→DisplayCoordinator→Applier→GammaController), read back directly: baseline midpoint (0.500, 0.500, 0.500) → after ON at 0K (0.500, 0.0, 0.0). |
| OFF restores to baseline | pass | Same run, immediately after: back to (0.500, 0.500, 0.500), exact match. |
| Real `Dimit.app`, cold launch with `isOn: true` persisted, applies gamma with zero interaction | pass | Seeded `state.v1` externally, launched the actual binary, read gamma back: (0.500, 0.0, 0.0) — proves the reactive pipeline's initial `reapply()` in `DisplayCoordinator.init` works, not just the manual-toggle path. |
| ⌘⇧4-equivalent screenshot while genuinely red | pass | Confirmed gamma was red via direct readback *at the same moment*, then screenshotted: fully normal colors. Stronger than the C0 check — this time the tint was independently proven to be actually active when the screenshot was taken. |
| `SIGTERM` while ON → clean quit + restore | pass | Real app, `kill -TERM`, process exits, gamma back to baseline. |
| `kill -9` while ON → then check | pass, with a genuine surprise | On **this macOS 27 beta build**, WindowServer restores the gamma table to baseline **immediately** when the owning process dies via SIGKILL — reproduced twice, both via the probe and the real app binary. This was not assumed going in; CLAUDE.md's own cited bugs (FB19136488, FB22273730) are exactly why gamma behavior is known to be inconsistent across macOS versions and hardware, so **the "restore on launch, before anything else" safety net stays in the code regardless** — it's a no-op here (nothing to restore) and a real fix on whatever macOS version doesn't auto-clean-up this way. Do not assume this finding generalizes; re-check on macOS 13–26 during beta. |

**Bug caught and fixed while writing `DisplayManager`, not found by review after the fact:** `deinit` originally called `CGDisplayRemoveReconfigurationCallback` with `userInfo: nil`, but registration used this instance's opaque pointer — a mismatch could leave a dangling registration pointing at freed memory the next time any display reconfigured.

**`/code-review high`, 8 parallel angles, 10 findings, all fixed** (see the PR for the full list): the two most significant were `verifyReadBack` only ever comparing the red channel (blind to exactly the green/blue corruption a Tahoe-class bug would cause) and a global-restore-ordering bug where `CGDisplayRestoreColorSyncSettings()` ran after per-display applies — invisible today since `Renderer`'s single global `isOn` flag can't produce a mixed toApply/toRestore diff, but `Applier` is already built and tested for that mix, and it would have silently wiped a still-on display's gamma the moment per-display control lands. Also fixed: a state-desync race in the "Restore Colours" button, failed gamma applies never being retried, a `MainActor.assumeIsolated` that could trap on an unproven thread guarantee (replaced with `Task { @MainActor in }`), a UUID-lookup fallback that could drift a display's baseline cache key on a transient failure, and a translation-process violation (shipped guessed uz/ru text instead of English + a review marker, per CLAUDE.md §5.1's explicit fallback). Re-ran the full integration probe against the real display after every fix: still passes. Fixed to pass the same pointer both times.
