## C2 — gamma engine (2026-09-09, MacBookPro18,1 M1 Pro, macOS 27.0 26A5416b, built-in display only)

Screenshots can't show a gamma tint (see the C0 row above), so every check below verifies by reading the live gamma table back directly with `CGGetDisplayTransferByTable` — a precise, vision-free check of the actual OS-level state, not an inference. Verification ran against **the real compiled `Dimit.app` binary**, not a reimplementation: a standalone probe copies the actual `Dimit/Display/*.swift` and `Dimit/App/AppState.swift` source files (same technique as C1's popover render check) and drives them directly, and separately the real `Dimit.app` was launched with its persisted state pre-seeded to `isOn: true` via `UserDefaults(suiteName: "app.dimit.mac")` from outside the process.

**Bug caught and fixed while writing `DisplayManager`, not found by review after the fact:** `deinit` originally called `CGDisplayRemoveReconfigurationCallback` with `userInfo: nil`, but registration used this instance's opaque pointer — a mismatch could leave a dangling registration pointing at freed memory the next time any display reconfigured.

**`/code-review high`, 8 parallel angles, 10 findings, all fixed** (see the PR for the full list): the two most significant were `verifyReadBack` only ever comparing the red channel (blind to exactly the green/blue corruption a Tahoe-class bug would cause) and a global-restore-ordering bug where `CGDisplayRestoreColorSyncSettings()` ran after per-display applies — invisible today since `Renderer`'s single global `isOn` flag can't produce a mixed toApply/toRestore diff, but `Applier` is already built and tested for that mix, and it would have silently wiped a still-on display's gamma the moment per-display control lands. Also fixed: a state-desync race in the "Restore Colours" button, failed gamma applies never being retried, a `MainActor.assumeIsolated` that could trap on an unproven thread guarantee (replaced with `Task { @MainActor in }`), a UUID-lookup fallback that could drift a display's baseline cache key on a transient failure, and a translation-process violation (shipped guessed uz/ru text instead of English + a review marker, per CLAUDE.md §5.1's explicit fallback). **Two real, verified findings about hardware/OS behavior, not assumptions**, both documented prominently in code comments so they aren't lost: `CoreDisplayBackend` doesn't actually control the built-in panel's brightness on this Apple Silicon machine (its `get()` is a constant), and the `IORegistry` brightness cross-check CLAUDE.md's own spec describes as "observed on the dev machine" does not track live changes on *this* dev machine as re-tested for this cycle. Both are implemented per spec regardless (harmless, and may behave correctly on hardware this session doesn't have), with the discrepancy flagged for whoever tests on a Studio Display, Pro Display XDR, or Intel Mac.

**`/code-review high`, 8 parallel angles, 10 findings, all fixed** (full list in the PR). Test count went 65 → 72. The three that mattered most:

- **Quitting with PWM-Safe on left the backlight stuck at 100%.** Gamma and overlays die with the process; a `DisplayServicesSetBrightness` write does not. `applicationWillTerminate` now calls `restoreAndDisable()`, and so does the "Restore colours" panic button (which previously restored gamma and the overlay synchronously but left the backlight to the deferred `reapply()` — exactly the pipeline-timing dependency that function's own comment says a panic button must not have).
- **The retry path violated CLAUDE.md §3.4's "never call set-brightness more than 4×/second."** Failed pins recursed immediately, firing all three attempts within a few milliseconds. Every retry is now spaced by the same delay as the verify.
- **Adding `fallbackMode` to `PersistedState` would have wiped every existing user's settings on upgrade.** Swift's synthesized `Decodable` throws `keyNotFound` for a missing non-optional key rather than defaulting it — verified empirically against an earlier assumption to the contrary, then fixed with a hand-written `init(from:)` using `decodeIfPresent` for every field. `DimitTests/PersistenceTests.swift` now pins that behaviour so the next added field can't regress it.

Also fixed: stale async verify callbacks from a previous enable landing on a re-enabled session (generation-based invalidation), `sync()` clobbering in-flight pin state on every pipeline pass, pinning a display whose brightness couldn't be read in the first place (nothing to restore on disable), a redundant per-pass rewrite of every overlay window's properties, and a duplicated `NSScreen`-by-`displayID` lookup. Re-ran the full hardware integration probe after the fixes: pin, verify, restore-to-exact-original, overlay geometry and Fallback-mode gamma all still pass on the real display.
